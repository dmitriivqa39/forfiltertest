AdGuard Extra Injection Check

Checks whether AdGuard Extra is installed, injected into this page, and active on this domain — in Chromium, Firefox, and Safari.

This page is opened from file://. AdGuard Extra's content script matches only http:// and https:// pages, so it will not inject here, and the extension probe cannot run. Serve the folder over HTTP, for example:
Command
python -m http.server 8000
then open http://localhost:8000/extra.html.

Injection check

AdGuard Extra has no public API. This page combines four independent layers: the extension resource, the observed injection event, the declarations a userscript leaves in the page world, and TinyShield instrumentation.

Self-test

Verifies the detector without relying on the current page. The direct test loads the official AdGuard Extra userscript into a hidden isolated frame. The build test inspects the userscript that the installed extension actually injects.

How it works

CheckWhat it looks forStrength
Extension resource A Chromium extension answers chrome-extension://<id>/userscript.js. The release and beta IDs are known and stable. Strong (installation)
Injection event An early MutationObserver catches an injected <script> whose text or src contains AdGuard Extra markers, even if the injector removes the tag afterwards. Works when the injection happens after the parser starts (AdGuard Mini / Safari, AdGuard apps, userscript managers). Strong (injection event)
Extra core globals Top-level declarations from an unwrapped AdGuard Extra build: shouldRunExtra, takeDomainsBlob, isTinyShieldAllowedForCurrentPage. Strong (page world)
TinyShield globals Internal TinyShield functions bundled into AdGuard Extra: EnableTinyShield, CreateTinyShieldController, Install*Patch. Strong (group)
pageCallback$*, _0x* Many top-level helpers specific to the obfuscated AdGuard Extra bundle. Indirect
Inline script An inline <script> whose text contains AdGuard Extra markers. Strong, if present
Function.prototype.toString TinyShield fakes native code for functions named toString, get or set. Active check
Map.get, Map.set TinyShield proxies these methods and stringifies arguments; a native Map never calls toString on a key or value. Active check
setTimeout Proxy trap frame in the stack when the timer stringifies its argument. Active check
The current extension build is wrapped. The Chrome Web Store release (1.1.41) injects userscript.js wrapped in (function () { … })();. Its declarations never reach window, so page-world markers are not expected with the extension. The page detects the extension resource, observes the injected script tag when the injector runs after the parser starts, and checks for active TinyShield patches.

AdGuard apps that inject the unwrapped userscript from userscripts.adtidy.org are detected through the leaked globals. If the code is injected in a wrapped scope, only the extension resource and active TinyShield checks can reveal anything.

Safari and Firefox. Safari WebExtensions use a stable safari-web-extension://<UUID> origin, and AdGuard Mini for Mac / AdGuard for Safari inject the userscript wrapped in an IIFE. The page watches for the injected script tag; if AdGuard Mini injects after the parser starts, it is caught even though the build is wrapped. If nothing is seen and there is no UUID (or active instrumentation), Safari reports Inconclusive instead of “Not detected”. AdGuard Extra is not available for Safari on iOS.
Advanced: probe a Safari extension by UUID

If you know the safari-web-extension:// origin of the AdGuard Mini web extension, paste it here. The page will probe adguard-extra.js and remember the value. You can find the origin in Safari's Web Inspector for the extension's background page (location.host).
